# Project-Spinup

> Create a new project in the Personal OS with all conventions in place. Works from any repo via MCP.

---

## When to Use

When Nigel starts a new project — client work, advisory, or personal build. This skill sets up the project folder, briefing, and wires it into the vault.

---

## Agent Behaviour

### 1. Classify
Determine the project type based on context:
- **SD-** (Service Delivery) — consulting, client work, paid engagements
- **RB-** (Relationship-Based) — advisory, helping someone, not direct employment
- **MY-** (My Own) — owned products, personal builds, experiments

### 2. Create
Use the `spinup_project` MCP tool (or create manually if in the vault):
- Folder: `Projects/{PREFIX}-{CODE}/`
- Briefing: `_Briefing-{code}.md` with standard template
- Projects map: automatically updated

### 3. Research
If the project is external (client, company), search the web for context:
- What the company/product does
- Market position, competitors
- Recent news, funding, team
- Any public information that enriches the briefing

### 4. Brief
Fill in the briefing with:
- Overview — what it is, what Nigel's role is
- Goals — what success looks like
- Key Decisions — blank to start, filled as they're made
- Working Notes — any initial context from Nigel

### 5. Log
Write a Memory entry (type: context) noting the new project was created and why.

---

## Quality Bar

- Does the briefing give an agent enough context to be useful on day one?
- Is the project code short and memorable?
- Is the type prefix correct? (SD for client work, not MY)

---

## Anti-Patterns

- **Creating a project without a briefing.** The folder alone is useless. Always write the briefing.
- **Skipping the map update.** The Projects map is how agents discover projects. If it's not in the map, it doesn't exist.
- **Over-filling on day one.** The briefing starts sparse and grows. Don't pad it with speculation.
