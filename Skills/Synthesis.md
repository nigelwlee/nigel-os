# Synthesis

> Take messy input. Produce a tight, actionable output a CEO could act on.

---

## When to Use

Any time Nigel drops unstructured or mixed input and needs it turned into something sharp. Inputs include: meeting notes, transcripts, research, Slack threads, data dumps, docs, voice memos, or any combination.

---

## Agent Behaviour

1. **Read everything first.** Don't start writing until you've processed all input.
2. **Find the so-what.** Before structuring output, identify the single most important takeaway or recommendation. Lead with it.
3. **Apply structured thinking.** Use pyramid principle: conclusion first, then supporting arguments, then evidence. Group insights MECE where possible.
4. **Be hypothesis-driven.** If the input implies a decision, state your recommended answer upfront and let the evidence support or challenge it.
5. **Strip ruthlessly.** Every sentence must earn its place. If removing a sentence loses nothing, remove it.

---

## Output Format

### TL;DR
One to three sentences. The recommendation or core takeaway. A busy person reads only this and can act.

### Key Insights
Numbered list, 3–7 items. These are insights, not summaries. Each should say something non-obvious or decision-relevant. Format: **bold claim** followed by one sentence of supporting evidence or context.

### Options (if applicable)
Only include if the input presents a genuine decision with trade-offs. Use a simple table or bullet structure: Option | Upside | Downside | Recommendation.

### Next Steps
Numbered list of specific, assignable actions. Each starts with a verb. Include owner or timeframe if the input provides enough context.

---

## Quality Bar

- Could you paste this into a Slack message to a CEO or client? If not, tighten it.
- Does the TL;DR stand alone? Someone who reads nothing else should still get the point.
- Are the insights actually insightful? "Revenue grew" is a summary. "Revenue grew despite churn doubling, which means new acquisition is masking a retention problem" is an insight.
- Is there a clear recommendation? If not, you haven't done your job.
- Is it under one page? Aim for it. Go longer only if the input genuinely warrants it.

---

## Anti-Patterns

- **Summarising instead of synthesising.** Restating what was said is not the job. The job is extracting meaning and implications.
- **Burying the lead.** Never put the recommendation at the end. It goes first.
- **Hedging.** "It might be worth considering..." — no. State what you think and why.
- **Including everything.** Not all input is signal. Leave out noise even if it was in the source material.
- **Generic next steps.** "Discuss further" or "align on next steps" are non-actions. Be specific or leave them out.
- **Fluff transitions.** No "In conclusion," or "It's worth noting that." Just say the thing.
